# Лабораторна робота 1 — Шифри заміни та перестановки

Реалізація чотирьох навчальних шифрів українською мовою (Go) з
нон-інтерактивним консольним інтерфейсом (прапорці командного рядка), плюс
усі п'ять додаткових завдань розділу 13.

Алгоритми **не призначені для захисту реальних даних** — вони навчальні
(розділ 3 завдання).

## Версія та залежності

- Go 1.22+ (перевірено на `go1.27.1`)
- `golang.org/x/text` — нормалізація Unicode NFC
- `github.com/joho/godotenv` — опційне завантаження `.env` з дефолтними ключами

Усі залежності зафіксовані в `go.mod` / `go.sum`. AES-GCM (додаткове
завдання, розділ 13) використовує лише стандартну бібліотеку (`crypto/aes`,
`crypto/cipher`) — AES самостійно не реалізовувався.

## Дефолтні ключі в .env

Щоб не передавати ключ у кожному виклику, скопіюйте `.env.example` у `.env`:

```bash
cp .env.example .env
```

При старті програма (якщо файл `.env` є в робочій директорії) підставляє
значення як постійний ключ кожного шифру — його конструктор отримує ключ
напряму (`composition_root.go`). Прапорець `-k` завжди має пріоритет над
`.env`. Це **не секрети**, а навчальні значення з умови лабораторної
(розділ 3 прямо дозволяє зберігати такі ключі у звіті); `.env` додано до
`.gitignore`.

Змінні:

| Змінна | Алгоритм |
| --- | --- |
| `LAB1_SUBSTITUTION_KEY` | проста підстановка (ключове слово) |
| `LAB1_VIGENERE_KEY` | шифр Віженера (ключове слово) |
| `LAB1_BLOCK_PERMUTATION_KEY` | блокова перестановка (напр. `3 2 5 1 4`) |
| `LAB1_COLUMNAR_KEY` | вертикальна перестановка (напр. `3 1 4 2`) |
| `LAB1_HOMOPHONIC_SEED` | гомофонна підстановка (додатково) — seed відтворюваності, не секрет; порожньо = системна випадковість |

```

internal/lab_1/                — композиція й диспетчеризація (не містить самих алгоритмів)
  composition_root.go          — єдине місце збирання залежностей (App, CipherService)
  service.go                   — CipherService: диспетчеризація за алгоритмом + валідація ключів
  config.go                    — завантаження дефолтних ключів з .env
  errors.go                    — ErrUnknownAlgorithm (помилка рівня сервісу)
internal/lab_1_algo/           — реалізації алгоритмів (обов'язкові + додаткові)
  cipher.go                    — спільний інтерфейс Cipher, тип Algorithm, Result
  alphabet.go                  — базовий алфавіт A (33 літери) та індексація
  textprep.go                  — NFC-нормалізація, верхній регістр, режим letters-only
  substitution.go              — проста одноалфавітна підстановка (4.2)
  vigenere.go                  — шифр Віженера (4.4)
  block_permutation.go         — блокова перестановка (4.5)
  columnar.go                  — вертикальна перестановка (4.6)
  permutation.go               — парсинг/валідація ключа-перестановки
  errors.go                    — помилки валідації ключів конкретних шифрів
  homophonic.go                — додатково: гомофонна підстановка (4.3, розділ 13)
  frequency.go                 — додатково: гістограма частот літер (розділ 13)
  vigenere_analysis.go         — додатково: оцінка довжини ключа Віженера (Касіскі, індекс збігів; розділ 13)
internal/lab_1_ext/            — допоміжний пакет: читання/запис UTF-8 файлів (file.go)
internal/lab_1_aes/            — додатково: AES-GCM через стандартну бібліотеку для порівняння (розділ 13)
tests/
  lab_1/                       — тести internal/lab_1 + internal/lab_1_algo (package lab_1_test)
  lab_1_ext/file_test.go       — тести файлового I/O (package lab_1_ext_test)
  lab_1_aes/aes_demo_test.go   — тести AES-GCM і порівняння з Віженером (package lab_1_aes_test)
  fixtures/                    — підготовчі дані для тестів (sample_utf8.txt, invalid_utf8.bin)
```

`internal/lab_1_algo` не залежить від `internal/lab_1`: алгоритми можна
використовувати напряму (як і роблять тести), а `internal/lab_1` лише додає
над ними шар диспетчеризації (`CipherService`) і збирання залежностей
(`composition_root.go`). `internal/lab_1_ext` (файловий I/O) та
`internal/lab_1_aes` (AES-GCM для порівняння) — окремі, незалежні пакети;
жоден із них не є частиною криптологіки самих навчальних шифрів.

Тести лежать окремо від реалізації, у `tests/`, і звертаються до пакетів
лише через публічний API (`import algo "4c-security-labs/internal/lab_1_algo"`
тощо), а підготовчі файли для тестів — у `tests/fixtures`.

## Запуск

```bash
go run ./cmd/lab_1 -a=<1..5> -e|-d [-k ключ] [-p N] [-i вхідний.txt] [-o вихідний.txt] [-freq] [текст]
go run ./cmd/lab_1 -a=2 -estimate-key-length [-i шифротекст.txt] [шифротекст]
# або через Makefile:
make run ARGS='-a=2 -e "СЛАВА УКРАЇНІ"'
```

Алгоритми (`-a`):

| № | Алгоритм |
| --- | --- |
| 1 | Проста одноалфавітна підстановка |
| 2 | Шифр Віженера |
| 3 | Блокова перестановка |
| 4 | Вертикальна перестановка |
| 5 | Гомофонна підстановка (додатково, розділ 13) |

Прапорці:

- `-a int` — номер алгоритму, 1–5 (обов'язково)
- `-e` / `-d` — зашифрування / розшифрування (рівно один з двох, обов'язково для алгоритмів 1–5; не потрібні з `-estimate-key-length`)
- `-k string` — ключ; якщо не задано, береться постійний ключ з `.env` для
  обраного алгоритму (для 1–4 помилка, якщо ключа немає в жодному з джерел;
  для гомофонної підстановки порожній ключ — це не помилка, а сигнал
  використати системну випадковість, розділ 4.3)
- `-p int` — кількість доданих службових символів; потрібна лише для
  розшифрування вертикальної перестановки (розділ 4.6), інакше ігнорується
- `-i string` — читати текст з UTF-8 файла замість позиційного аргументу
- `-o string` — записати результат у UTF-8 файл замість stdout
- `-freq` — додатково: вивести у stderr гістограму частот літер вхідного і
  вихідного тексту (розділ 13)
- `-estimate-key-length` — додатково: разом з `-a=2` не шифрує/розшифровує,
  а оцінює довжину ключа Віженера в переданому шифротексті методами
  Касіскі та індексу збігів (розділ 13)
- позиційний аргумент — сам текст (якщо `-i` не задано)

Приклади:

```bash
go run ./cmd/lab_1 -a=2 -e "СЛАВА УКРАЇНІ"
# ВЬЮЩК ДЇККЧЛД

go run ./cmd/lab_1 -a=2 -d "ВЬЮЩК ДЇККЧЛД"
# СЛАВА УКРАЇНІ

go run ./cmd/lab_1 -a=4 -e "КРИПТОГРАФІЯ"
# ИГІКТАПРЯРОФ  (+ у stderr: кількість доданих символів, якщо є доповнення)

go run ./cmd/lab_1 -a=4 -d -p 0 "ИГІКТАПРЯРОФ"
# КРИПТОГРАФІЯ

go run ./cmd/lab_1 -a=1 -e -i input.txt -o output.txt

go run ./cmd/lab_1 -a=5 -e "ПРИВІТ"
# напр. 66 69 34 12 35 79 (коди гомофонної підстановки; за замовчуванням випадкові щоразу)

go run ./cmd/lab_1 -a=1 -e -freq "СЛАВА УКРАЇНІ"
# результат шифрування + гістограми частот вхідного/вихідного тексту в stderr

go run ./cmd/lab_1 -a=2 -estimate-key-length -i ciphertext.txt
# оцінка довжини ключа методами Касіскі та індексу збігів
```

Для вертикальної перестановки `-e` виводить у stderr кількість доданих
службових символів — саме це число (а не довільну кількість символів)
потрібно передати через `-p` при розшифруванні (розділ 4.6).

Некоректний ключ, невідомий алгоритм, брак тексту чи обидва/жодного з
`-e`/`-d` одразу повертають зрозуміле повідомлення в stderr і код виходу 1
(`go run ./cmd/lab_1 -h` — довідка з повним списком прапорців).

## Тестування

```bash
go test ./tests/...
# або
make test
```

Усі тести лежать окремо від реалізації, у `tests/` (пакети `lab_1_test`,
`lab_1_ext_test`, `lab_1_aes_test` — усі зовнішні до пакетів, які тестують),
а підготовчі файли, які вони читають, — у `tests/fixtures/`
(`sample_utf8.txt`, `invalid_utf8.bin`). Набір покриває:

- усі чотири контрольні вектори з розділу 7 (разом із перевіркою
  відновлення відкритого тексту);
- зворотність `D_k(E_k(x)) = x` для 10 різних повідомлень на кожен з
  чотирьох обов'язкових алгоритмів;
- окрему перевірку літер Ґ, Є, І, Ї;
- граничні випадки: порожній текст, один символ, довжина рівна блоку/числу
  стовпців, на один менша і на один більша;
- форматування (пробіли, перенос рядка, цифри, розділові знаки);
- негативні сценарії: порожній ключ, повтори/вихід за межі діапазону в
  перестановці, літера поза ключовим алфавітом Віженера, кількість
  доповнення поза допустимим діапазоном;
- ін'єкцію постійного ключа через конструктор кожного шифру та `CipherService.DefaultKey`;
- читання/запис UTF-8 файлів та відхилення некоректного UTF-8;
- усі п'ять додаткових завдань розділу 13 (див. нижче).

### Примітка щодо контрольних векторів із PDF

Два з чотирьох контрольних векторів у наданому завданні, судячи з усього,
постраждали від артефактів вилучення тексту з PDF:

- приклад зворотного алфавіту показує шифротекст `ІНЬЯ ЗОЇЯРЛС` (11 літер)
  для відкритого тексту з 12 літерами без пробілу — бракує однієї літери;
- приклад шифру Віженера на позиції 7 показує `І`, хоча формальний
  розрахунок за наведеною формулою `C_i = (P_i + K_i mod l) mod m` дає `Ї`
  (ці літери відрізняються лише діакритичними крапками, що типово для
  OCR-помилок).

Решта символів обох векторів, а також вектори блокової та вертикальної
перестановки, повністю збігаються з розрахунком за формальними означеннями
з розділів 4.2–4.6. У тестах використано значення, обчислені безпосередньо
за цими означеннями (`ІНЯЬЯ ЗОЇЯРЛС` та `ВЬЮЩК ДЇККЧЛД` відповідно); якщо
очікується буквальний збіг із текстом PDF, достатньо замінити дві літери
в `tests/lab_1/cipher_test.go`.

## Алфавіт

Базовий алфавіт A — стандартні 33 великі літери сучасної української абетки
(включно з Ґ), m = 33:

```
АБВГҐДЕЄЖЗИІЇЙКЛМНОПРСТУФХЦЧШЩЬЮЯ
```

## Єдина специфікація обробки тексту (розділ 5)

- Кодування: UTF-8, програма працює з Unicode-рядками.
- Нормалізація: Unicode NFC перед будь-якою обробкою (`textprep.go`).
- Регістр: базовий режим переводить літери у верхній регістр.
- Сторонні символи (пробіли, цифри, розділові знаки) зберігаються і не
  зсувають позицію ключа Віженера.
- Перестановки мають режим `preserve` (зберігає всі символи, зворотний) та
  `letters only` (лише для історичного прикладу, незворотний щодо пробілів).
- Некоректний ключ або непідтримуваний символ повертає зрозуміле повідомлення
  про помилку, без аварійного завершення.

## Додаткові завдання (розділ 13)

### 1. Гістограма частот для простої підстановки

`-freq` (CLI) / `algo.LetterFrequencies`, `algo.FrequencySorted`
(`internal/lab_1_algo/frequency.go`). Проста підстановка — бієкція на
алфавіті: вона лише переставляє, яка літера несе яку частоту, тому
*мультимножина* кількостей (форма гістограми без прив'язки до конкретних
літер) у відкритому тексті й шифротексті однакова — лише підписи стовпців
різні. Саме тому проста підстановка вразлива до частотного аналізу:
атакувальник, побачивши форму гістограми шифротексту, вже знає форму
гістограми відкритого тексту і лишається тільки підібрати відповідність
літер. Формально перевірено в
`TestSubstitutionPreservesFrequencyMultiset` (`tests/lab_1/frequency_test.go`).

### 2. Гомофонна підстановка з відтворюваним тестовим режимом

`-a=5` (CLI) / `algo.NewHomophonicCipher` (`internal/lab_1_algo/homophonic.go`).
100 двозначних кодів `00`–`99` розподіляються між 33 літерами пропорційно
приблизній частотній таблиці (метод найбільшого залишку, кожна літера
отримує щонайменше один код). Ключ — це опційний seed відтворюваності
(розділ 4.3): непорожній ключ детерміновано ініціалізує генератор (той самий
seed + той самий текст → той самий шифротекст — зручно для тестів), а
порожній ключ використовує системне криптографічне джерело випадковості
(`crypto/rand`) для непередбачуваного вибору гомофона при кожному виклику.
Розшифрування не залежить від ключа (таблиця код→літера фіксована).
Тести: `tests/lab_1/homophonic_test.go`, `tests/lab_1/homophonic_table_test.go`.

### 3. Оцінка довжини ключа Віженера

`-estimate-key-length` (CLI, разом з `-a=2`) /
`algo.KasiskiCandidates`, `algo.EstimateVigenereKeyLengthByIC`
(`internal/lab_1_algo/vigenere_analysis.go`). Метод Касіскі шукає повторені
підрядки в шифротексті й ранжує кандидатів на довжину ключа за тим, скільки
відстаней між повторами вони ділять націло. Метод індексу збігів перевіряє
кожну довжину L: розбиває шифротекст на L підпослідовностей (по одній на
позицію ключа) і усереднює їхній індекс збігів — підпослідовність під одним
незмінним зсувом лишається «схожою на текст» (високий IC), а суміш кількох
зсувів — «схожою на випадковість» (IC ≈ 1/33); обирається найменша довжина
з помітно підвищеним IC (кратні довжини теж дають підвищений IC, тому
береться найменша, а не з найвищим балом). Перевірено на довгому тексті
(~700+ літер) з відомою довжиною ключа: `tests/lab_1/vigenere_analysis_test.go`.

### 4. Генеративні тести

`tests/lab_1/property_test.go`: для кожного з п'яти алгоритмів (1–5) по 50
випадкових коректних пар (ключ, повідомлення) — з детермінованим `math/rand`
seed заради відтворюваності прогону — перевіряють `D_k(E_k(x)) = x`.
Повідомлення навмисно змішують літери алфавіту з пробілами, цифрами й
розділовими знаками, щоб заразом перевірити й збереження сторонніх символів.

### 5. Порівняння з AES-GCM

`internal/lab_1_aes/aes_demo.go` — тонка обгортка над `crypto/aes` і
`crypto/cipher` стандартної бібліотеки (AES самостійно не реалізовувався).
`tests/lab_1_aes/aes_demo_test.go` демонструє:

- **роль nonce**: `Seal` генерує новий випадковий nonce щоразу, тому
  шифрування того самого повідомлення тим самим ключем двічі дає різні
  байти (`TestAESGCMNonceIsUniquePerCall`) — на відміну від навчальних
  шифрів, де однаковий (ключ, текст) завжди дає однаковий шифротекст;
- **відмову розшифрування після зміни шифротексту**: зміна навіть одного
  біта в nonce, шифротексті чи тегу автентифікації змушує `Open`
  повернути помилку (`TestAESGCMRejectsTamperedCiphertext`,
  `TestAESGCMWrongKeyFails`) — GCM перевіряє цілісність і автентичність, а
  не лише конфіденційність;
- **контраст із Віженером**: `TestComparisonVigenereHasNoTamperDetection`
  показує, що зміна літери в шифротексті Віженера «розшифровується» без
  жодної помилки — просто в інший, неправильний відкритий текст, без
  жодного сигналу про втручання.

# Лабораторна робота 2 — Квадрат Полібія та шифр Гронсфельда

Реалізація координатного режиму квадрата Полібія, режиму циклічного зсуву
за рядками того самого квадрата та шифру Гронсфельда (Go), для
українського (33 літери + 0,1,2 → квадрат 6×6) і латинського (26 літер +
0–9 → квадрат 6×6) наборів символів.

Алгоритми **не призначені для захисту реальних даних** — вони навчальні
(розділ 3 завдання).

## Структура проєкту

```
cmd/lab_2/main.go              — точка входу: парсинг прапорців, виклик сервісу, вивід
internal/lab_2/                — композиція й диспетчеризація (не містить самих алгоритмів)
  composition_root.go          — єдине місце збирання залежностей (App, CipherService)
  service.go                   — CipherService: диспетчеризація за алгоритмом + валідація ключів
  errors.go                    — ErrUnknownAlgorithm
internal/lab_2_algo/           — реалізації алгоритмів
  cipher.go                    — спільний інтерфейс Cipher, тип Algorithm, Result
  alphabet.go                  — мови (Language), базові набори літер і квадрата (36 символів)
  textprep.go                  — NFC-нормалізація, верхній регістр
  square.go                    — побудова квадрата 6×6 (4.3), координати (4.4), циклічний зсув (4.5)
  polybius_coordinates.go      — координатний режим Полібія
  polybius_rowshift.go         — режим циклічного зсуву за рядками
  gronsfeld.go                 — шифр Гронсфельда (4.7)
  errors.go                    — помилки валідації ключів/квадрата/токенів
tests/lab_2/                   — тести internal/lab_2 + internal/lab_2_algo (package lab_2_test)
```

Криптографічна логіка (`internal/lab_2_algo`) не залежить від
`internal/lab_2` і може використовуватись напряму (так само роблять тести).
Файловий UTF-8 I/O (`ReadUTF8File`/`WriteUTF8File`) переюзаний із
`internal/lab_1_ext` — це мовно-незалежний допоміжний код, що не містить
крипто-логіки жодної з лабораторних робіт.

## Запуск

```bash
go run ./cmd/lab_2 -a=<1..3> -lang=ua|lat -e|-d -k ключ [-i вхідний.txt] [-o вихідний.txt] [-show-square] [текст]
# або через Makefile:
make run2 ARGS='-a=3 -lang=lat -e -k "2718" "HELLO WORLD"'
```

Алгоритми (`-a`):

| № | Алгоритм |
| --- | --- |
| 1 | Квадрат Полібія — координатний режим |
| 2 | Квадрат Полібія — циклічний зсув за рядками |
| 3 | Шифр Гронсфельда |

Прапорці:

- `-a int` — номер алгоритму, 1–3 (обов'язково)
- `-lang string` — `ua` (український набір) або `lat` (латинський набір); обирається явно, автовизначення мови не допускається (розділ 5)
- `-e` / `-d` — зашифрування / розшифрування (рівно один з двох, обов'язково)
- `-k string` — ключ: ключове слово квадрата (алгоритми 1–2) або рядок цифр (алгоритм 3, зберігається як рядок — початкові нулі не губляться)
- `-i string` / `-o string` — UTF-8 файл замість позиційного аргументу / stdout
- `-show-square` — вивести у stderr побудований квадрат 6×6 (лише для алгоритмів 1–2)

**Координатний режим (алгоритм 1) на базовому рівні приймає лише символи
обраного квадрата** — пробіли та розділові знаки потрібно прибрати з
тексту заздалегідь, це свідома, видима дія підготовки тексту (розділ 4.1),
а не прихована нормалізація всередині шифру.

Приклади:

```bash
go run ./cmd/lab_2 -a=1 -lang=ua -e -k "БЕЗПЕКА" "СЛАВА"
go run ./cmd/lab_2 -a=1 -lang=ua -d -k "БЕЗПЕКА" "44 35 16 21 16"
go run ./cmd/lab_2 -a=2 -lang=ua -e -k "БЕЗПЕКА" "СЛАВА"
go run ./cmd/lab_2 -a=3 -lang=lat -e -k "2718" "HELLO WORLD"
go run ./cmd/lab_2 -a=1 -lang=ua -e -show-square -k "БЕЗПЕКА" "СЛАВА"
```

## Контрольні вектори (розділ 7 умови)

| Алгоритм, мова | Ключ | Відкритий текст | Очікуваний результат |
| --- | --- | --- | --- |
| Полібій coordinates, укр. | БЕЗПЕКА | СЛАВА | `44 35 16 21 16` |
| Полібій coordinates, лат. | SECURITY | HELLO | `32 12 35 35 42` |
| Полібій row shift, укр. | БЕЗПЕКА | СЛАВА | `ЧТЖИЖ` |
| Полібій row shift, лат. | SECURITY | HELLO | `OYVVZ` |
| Гронсфельд, укр. | 31415 | СЛАВА УКРАЇНІ | `ФМҐГД ЦЛФБНРЇ`¹ |
| Гронсфельд, лат. | 2718 | HELLO WORLD | `JLMTQ DPZNK` |

¹ У тексті умови лабораторної цей вектор надруковано як `ФМІГД ЦЛФБНРЇ`.
Ручне обчислення за формулою розділу 4.7 (`m=33`, цифри ключа 3,1,4,1,5
циклічно застосовуються лише до літер, пробіл зберігається і не споживає
цифру) дає `ФМҐГД ЦЛФБНРЇ`: третя літера — `А`+4 = індекс 4 = `Ґ`, а не
візуально схожу `І` з умови — той самий тип одно-гліфового артефакту
розпізнавання, що вже задокументований для контрольних векторів
лабораторної роботи 1. Усі інші символи обох половин збігаються з умовою
точно; `tests/lab_2/cipher_test.go` фіксує обидва значення в коментарі.

Усі шість векторів, включно з відновленням відкритого тексту
(`Decrypt(Encrypt(x)) = x`), перевірені тестами
`TestControlVectorPolybius*`, `TestControlVectorGronsfeld*`.
